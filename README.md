# Open Field

A browser-based 3D open world with a third-person character, built from nothing
but code. There are no downloaded models, no textures on disk, and no
hand-authored animation. Every asset — the character mesh, its skeleton, its
animation clips, the terrain, the ambient occlusion, the prop placement — is
generated by a Node build step and written out as binary data the browser loads.

```bash
npm install
npm start          # build assets, then serve on http://localhost:5173
```

Controls: **WASD** move, **shift** sprint, **space** jump, **mouse** look
(click to capture), **wheel** zoom, **F** detached camera, **T** advance time of
day, **P** pause the day cycle.

---

## Why generate instead of download

The obvious way to put a character in a scene is to fetch a rigged model and
load it. That was the original plan and it does not survive contact with
reality: the model sites gate downloads behind authentication, so the pipeline
would depend on scraping something that can disappear. Synthesising the mesh
removes the dependency entirely, makes the result identical on every machine,
and — more usefully — means the silhouette and the skeleton are derived from one
shared table of measurements, so changing a number moves both.

## How the character is made

`tools/build-character.mjs`, about 2.7 seconds end to end.

1. **Implicit surface.** The body is a signed distance field: blended spheres
   and tapered capsules for the torso, head, ears, limbs and feet, plus a
   flattened zigzag for the tail. `ANATOMY` at the top of the file is the single
   source of truth — the field and the rig both read from it.

2. **Meshing.** `tools/lib/surfacenets.mjs` implements naive surface nets rather
   than marching cubes: no 256-entry triangle table, far more uniform topology,
   and the dual formulation makes quad emission trivial. Vertices are seeded
   from edge crossings then pushed onto the true isosurface with two Newton
   steps, which recovers the sharpness that surface nets normally rounds off
   ear tips and tail notches into.

   One detail that mattered: the tail segments are hard-unioned with `min`, not
   `smin`. Smoothing those joints is exactly what turns a lightning bolt into a
   featureless paddle.

3. **Colour.** A classifier runs per vertex — ear tips, back stripes, tail base
   — and writes vertex colours, converted from sRGB to linear because that is
   what glTF expects. The face is separate parametric geometry (eyes, glints,
   cheek pouches, nose, mouth) appended into the same buffers and bound rigidly
   to the head joint; resolving crisp circles from the volumetric mesh would
   have needed several times the triangle budget.

4. **Rigging.** A 21-bone skeleton whose rest pose is translation-only, which
   makes every inverse bind matrix a plain negated translation. Weights come
   from a Gaussian falloff on distance to each bone's segment, top four,
   normalised. The tail bones carry an extra positional mask, because a pure
   distance falloff drags the lower back around with the tail.

5. **Animation.** Four clips — idle, walk, run, jump — baked by sampling
   analytic pose functions at 20–30 fps. Keyframes are just samples, so
   retiming a clip is a one-line change.

6. **Export.** `tools/lib/glb.mjs` is a small glTF 2.0 writer. Three.js's
   exporter expects a DOM, and a GLB is only JSON plus a binary buffer, so
   writing the container directly was less work than shimming a browser.

Result: ~82k triangles, 2.9 MB, valid glTF.

## How the world is made

`tools/build-world.mjs`, about 1 second.

- **Terrain** — domain-warped fBm for hills, ridged multifractal masked to the
  world edge for a mountain rim that hides the boundary, a Gaussian basin for
  the lake, and a compression band around the waterline so shores are beaches
  rather than cliffs. Baked to a 320² `Float32Array`.
- **Ambient occlusion** — horizon tracing, 12 directions × 14 steps per texel,
  roughly 17M samples. Doing this offline costs the player nothing.
- **Props** — jittered-grid scatter with rejection rules on height, slope and a
  low-frequency density field, so forests clump instead of speckling.

Everything ships as raw binary plus a small JSON manifest.

## Runtime

Plain ES modules and an import map — no bundler. `tools/serve.mjs` serves the
app, the baked assets, and three.js out of `node_modules`.

| File | Role |
| --- | --- |
| `web/src/heightfield.js` | Shared sampler. Terrain, character grounding, grass and props all read through it, which is what guarantees the character stands on the surface that is actually drawn. |
| `web/src/terrain.js` | Mesh from the heightfield, analytic normals, per-vertex biome blend with baked AO folded in. |
| `web/src/sky.js` | Gradient dome, star field, and the palette that fog, lights and water tint all read from, so the scene changes colour as one. |
| `web/src/water.js` | Depth baked per vertex; quads entirely above the waterline are dropped. |
| `web/src/grass.js` | A finite patch that re-seeds when the player leaves its cell. Wind is applied in the vertex shader in world space — blades carry a random yaw, so the shader recovers it from the instance matrix to stop every blade blowing a different way. |
| `web/src/player.js` | Controller and animation state machine. Clip choice and playback rate both come from ground speed, which is what keeps the feet from skating. |
| `web/src/props.js`, `effects.js`, `camera.js`, `input.js`, `hud.js` | Instanced scenery, pooled particles, follow/free cameras, input, HUD. |

Thirteen draw calls for the whole scene.

## Verification

`npm run shoot` drives the app in headless Chromium and writes a set of
screenshots to `shots/`, including three of the character alone against a flat
background. It reports console errors and renders the scene at several times of
day. Two things worth knowing if you run it:

- Headless uses SwiftShader, so the scene renders at 1–5 fps. That is the
  software rasteriser, not the app. The harness therefore waits on *rendered
  frames* rather than wall-clock time, because the camera smoothing is
  per-frame and a fixed sleep captures the rig mid-interpolation.
- The FPS readout in the HUD uses unclamped frame time. The simulation clamps
  its timestep so a stalled tab cannot teleport the character, but reporting
  that clamped value as FPS would have the HUD cheerfully claim 20 fps while
  the renderer crawls.

## Known limitations

- No level of detail. Trees and terrain draw at full resolution regardless of
  distance; fine at this world size, not at ten times it.
- Collision is heightfield-only. Nothing stops you walking through a tree.
- Deep water is a wall rather than a swim state.
- Mouse-look assumes a pointer. There is no touch input.
